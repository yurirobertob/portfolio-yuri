The problem

A number that lies with false precision

Most growth dashboards report a bare percentage: 29% of subscribers did X. Cerebro's GoScout panel runs on 99 users. A four-person swing between two groups that small looks identical to a coin flip, and a bare percentage never admits it.

I built this panel to stop myself from reading noise as a strategy. Every rate on it is a Wilson 95% confidence interval, not a point estimate, and a row only earns the label “signal” when the paid interval and the free interval stop overlapping. Most rows on most days do not qualify, and the panel says that plainly instead of picking a winner anyway.

Design decisions

Four calls that shaped it

A bar instead of a number

Every rate renders as IntervalBar, a component that draws the Wilson 95% range as a filled span with a tick at the point estimate, width normalised so rows on the same table share one scale. This screen shows a range instead of a clean 29%, and a wide range is itself the finding.

The cost: the page never gives up a tidy headline number to repeat in a meeting. I took that trade because the tidy number was the thing lying.

A signal only counts when two bars stop touching

A row gets the green “sinal” tag only when the subscriber interval and the free interval have no overlap. Sorting by raw percentage would surface whichever row got lucky this week; sorting by non-overlap surfaces the handful of rows the sample can defend.

The cost: with under 100 users, most actions do not qualify yet, so the page mostly reports what it cannot conclude. A dashboard optimistic about a small sample teaches a false lesson, and I would rather ship the honest, thinner one.

Card is dashboard vocabulary, so it left

The first version boxed every section in a bordered card, indistinguishable from any SaaS admin panel. I redesigned it around the same rule I hold my own portfolio to: content first, frame gone. Sections separate by a hairline, numbers run large and typographic, and a numbered label replaces the plain heading.

The cost: every other screen in Cerebro still uses cards, so this page now looks like it belongs to a different app. I left it that way on purpose. It is the page making the argument the rest can follow later.

A number that only lives in the snapshot

An early version of this page had a hand-written line comparing paid traffic speed against the account average, copied from a GA4 read while the platform was still reprocessing attribution. Two days later the real number had moved and the panel kept repeating the old one, because it lived in a sentence I wrote, not in the data.

What changed: no number gets typed into the copy anymore. Every figure renders from the same snapshot the page reads live, so a stale read expires with the data instead of outliving it in a paragraph.

What it found

The one event the ad campaign is not optimising for

Across the actions the panel tracks, accepting a push notification is the strongest candidate for an activation event: it shows up more in paying users than in free ones, and the two intervals clear each other by the widest margin on the table. The Meta campaign feeding this product still optimises toward “Concluir inscrição”, a step that happens before anyone has done anything the data ties to paying.

That gap is the panel doing its job. It surfaced one specific event to hand a media buyer, with the confidence interval attached so nobody mistakes it for certainty it has not earned.

Takeaway

What this project shows

I build the measurement before I trust the decision. A confidence interval on every row is more work than a percentage, and it is the difference between a dashboard and an instrument.

I know when not to conclude. Most of this panel's rows say “not yet known” on any given day. Shipping that admission is harder than shipping a chart that always looks decisive.

My design rules travel. The same editorial discipline that shaped this portfolio, no card, no frame competing with the content, now runs an internal analytics screen I check daily.
