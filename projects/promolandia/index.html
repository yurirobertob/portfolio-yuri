A note on what this is

This isn't an interface project, and I'm not presenting it as one. Promolândia is a systems and growth-engineering project — it earns its place here because it's the clearest evidence of the engineering half of how I work, and because the feedback loop it runs is the same one that informs my design decisions elsewhere.

The problem

Brazilian shoppers rely on "deal-finder" groups on WhatsApp and Telegram to catch discounts before stock runs out. Almost all of them are one person copy-pasting links all day. That doesn't scale, doesn't run overnight, and can't prioritise by category or timing.

I replaced the manual layer entirely: a backend service that finds genuine discounts across four marketplaces, scores them, deduplicates them, and publishes them automatically — with affiliate monetisation and click tracking built in from the start rather than bolted on.

Engineering decisions

Four marketplaces, four different fights

One integration pattern per platform, because none of them behave the same

Mercado Livre has no official deals API, so this runs as server-side scraping behind a custom anti-bot layer — rotating browser headers, cookie persistence across paginated requests, randomised jitter between calls — to stay under an in-house detection system at zero API cost.

Amazon blocks at the infrastructure level: a WAF plus a JavaScript challenge on any datacentre IP. No amount of header tuning gets past that, so I stopped trying and routed through a search API instead — which also halved the request count versus the naive approach while tripling the yield of results carrying valid original-price data.

Shopee and AliExpress run on their official affiliate APIs once I was approved — GraphQL and REST respectively, including bulk LLM-based title translation, since the AliExpress feed returns English titles for a Portuguese-speaking audience.

The judgement call Knowing when to fight a defence and when to stop. Scraping was right for Mercado Livre and wrong for Amazon, and the difference is whether the blocker is heuristic or structural.

"A good deal" means something different on every platform

A single scoring model across four marketplaces would have been simpler and would have performed badly. Each platform's audience buys differently, so each gets its own weighted model: Mercado Livre is impulse territory and weights absolute price heavily; Amazon skews electronics and shifts weight to rating, review count and category; Shopee factors historical sales volume in.

All of them share one hard filter that runs before scoring: a minimum genuine discount. No amount of favourable weighting can rescue an item that isn't actually a deal.

Deduplication as a quality gate

The fastest way to lose an audience is to post the same product three times because it comes in three sizes. A title-normalisation step strips units, sizes, numbers and stopwords, then blocks near-duplicates across a seven-day rolling window — scoped per platform, so overlapping inventory between marketplaces doesn't produce false positives.

Measurement built into the link, not added later

Every outbound link is rewritten through a self-hosted shortener that logs each click with a timestamp. That feeds a dashboard showing volume by hour, weekday, platform and category — which closes the loop from what we post to what people actually click, and then feeds back into what gets prioritised.

This is the part that makes it growth engineering rather than automation. A script that posts things is a script. A pipeline that measures its own output and adjusts is a system.

What this project actually demonstrates

That I ship against hostile constraints. Two of these four integrations actively did not want to be integrated with. Getting them working meant understanding what kind of defence I was up against and choosing a different strategy for each.

That I think in feedback loops. The analytics layer wasn't a phase-two nice-to-have — it shipped with the first version, because a distribution system with no measurement is guesswork with extra steps.

That things I build keep running. This has published thousands of items without manual intervention. Shipping isn't the finish line; unattended operation is.

On how it was built: every layer, including the marketplace integrations and scoring logic, was built in close pair-programming with Claude Code.
